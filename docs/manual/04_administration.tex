\section{System Administration}

Administrators hold the responsibility of managing system configuration, backups, and user access.

\subsection{Managing User Roles}
User roles dictate what an employee can view or edit within the ERP.
\begin{enumerate}
    \item Navigate to \textbf{Settings > Users \& Companies > Users}.
    \item Select a user and adjust their access rights (e.g., granting "Administrator" rights for Inventory while leaving them as "User" for Purchase).
\end{enumerate}

\begin{alertbox}
    Only grant Administrator privileges to trusted personnel. Administrators can modify system data, delete records, and alter QWeb templates.
\end{alertbox}

\subsection{Maintaining QWeb Templates}
Custom PDF templates (such as the Purchase Order and Issue Note) are built using QWeb views inside the \texttt{drone\_traceability} module.

If structural changes are required (e.g., adding a new signature field):
\begin{itemize}
    \item Developers modify the XML files in the \texttt{custom-addons/drone\_traceability} directory.
    \item Administrators must restart the Odoo service and upgrade the module for changes to take effect.
\end{itemize}

\subsection{Docker Infrastructure}
The Drone ERP is containerized using Docker. To apply backend changes or restart the system, use the following commands in the server terminal:

\begin{lstlisting}[language=bash, caption={Basic Docker Commands for ERP Maintenance}]
# Restart the Odoo container
sudo docker compose restart odoo

# View real-time logs for troubleshooting
sudo docker compose logs -f odoo

# Completely stop the ERP stack
sudo docker compose down
\end{lstlisting}

\subsection{Database Backups}
Database backups should be taken routinely. Use the Odoo Database Manager (\texttt{http://[server-ip]:8069/web/database/manager}) to generate a \texttt{.zip} archive containing the SQL dump and the filestore.
